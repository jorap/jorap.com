When I got serious about web work, "open source" wasn't a conference sticker. It was the shelf I could afford - and I'm still glad that shelf was there.

Proprietary CMS licenses, boxed design software, monthly platform fees - fine if someone else pays. When you're learning, freelancing, or teaching students scraping together a laptop, **no license fee** is the difference between trying the thing this week or putting it off for a year.

What kept me wasn't "free." It was **freedom**. For the longer career arc - Drupal vs WordPress, teaching in the Philippines, what I run today - see [why I focused on open source technologies](/blog/why-i-focused-on-open-source/). This post is the filter I still use when someone asks if FOSS is worth the hassle.

---

## What freedom actually means here

**Install without asking permission.** Break things on your own machine. Read the source when the docs lie.

**Hand a client something they own.** A repo beats "call me when the license renews."

**Move when the host changes.** [Losing PHP hosting](/blog/how-i-built-jorap-notes/) locked this in: markdown in Git outlives any one provider. Hugo + GitHub + Cloudflare Pages wasn't "I love Go." It was files I can clone and point somewhere else.

Freedom still costs time. WordPress took months before I trusted myself on a live site. Hugo took another stretch before builds felt normal. Open source lets you learn on your schedule. It doesn't skip the learning.

Small businesses hit the same wall from the other side: license ate the margin, so they needed stacks they could customize. **Someone still paid in expertise** - a freelancer or the owner's weekends on plugins. Freedom to adapt, not a finished product in a box.

---

## The three-question filter

Before I adopt a tool - open or not - I ask:

1. **Can I inspect it?** Last month a Hugo partial threw a blank page. I opened the theme file, found a nil check someone forgot, fixed it in ten minutes. No ticket queue. A fatal WordPress plugin error? The code is right there.

2. **Can I move it?** Markdown in Git, standard SQL dumps, export that doesn't wait until I'm desperate. Closed tools tend to trap exports until you need them.

3. **Can I find help?** Thin communities cost hours. Thick ones save weeks. I chose WordPress partly because the bench was deeper, not because the logo was prettier.

If yes to all three, it gets a serious look. If no to move or inspect, I'm renting permission whether or not the sticker says open source.

---

## What it doesn't mean

Not a purity test. There's a gallery-slider plugin in a client install that hasn't seen a commit since 2019. Open doesn't mean maintained or good.

No license fee isn't no cost. Evenings on tutorials and broken staging sites. Domains still cost money. Bitwarden's family plan is one I pay for happily. Open at the core, paid where hosted convenience earns it.

I don't hand-roll themes for ego. I'd rather start from Hugoplate than reinvent what others already tested. Using open source doesn't put me in debt to it - I'm not obligated to ship patches or talk at meetups. Gratitude is fine. Guilt isn't part of the license.

---

## Starting out without a manifesto

Need a site you can afford to keep? Static generator, markdown in Git.

Need client work next quarter? Go where job posts are - WordPress for a long time in my market.

Need to trust a tool with secrets? Open source plus a real security track record, not marketing copy.

I pick for **freedom, ownership, and community depth**, not just "is it free." Glad the freedom was worth the months. Still is.
